VEDIKA PROJECT OVERVIEW
========================

ABOUT THIS DOCUMENT
-------------------
This document describes the Vedika codebase as it exists in the repository. It is a text-only guide for developers and project reviewers. It is not a user manual or a statement that every screen is connected to a live service.

PROJECT SUMMARY
---------------
Vedika is a browser-based event decoration design workspace. It is built for planning visual concepts for weddings, celebrations, and other events. Users can compose a decoration scene from reusable visual elements, start from editable layouts, manage design and moodboard records, and optionally collaborate through guest share links. The app also includes booking request screens and an admin review flow.

The interface is branded around event styling and uses a responsive application shell, a sidebar/header, reusable UI components, and an illustrated design canvas. Its interface supports English and Telugu. The project is a front-end single-page application; Supabase is an optional backend for authentication and persistence.

TECHNOLOGY
----------
- React 19 and React DOM for the UI.
- JavaScript ES modules with JSX.
- Vite 7 for development and production bundling.
- Tailwind CSS 4 through the Vite integration, plus project CSS.
- React Router for client-side navigation.
- Supabase JavaScript client for optional authentication and database access.
- lucide-react for icons, clsx for class composition, uuid for identifiers, and html-to-image for PNG canvas export.
- Vercel rewrite configuration routes browser paths back to the single-page app entry point.

RUNNING LOCALLY
---------------
Requirements: a compatible Node.js/npm installation.

1. Install dependencies from the project root:
   npm install
2. Start the Vite development server:
   npm run dev
3. Open the local URL printed by Vite (typically http://localhost:5173).

Available scripts:
- npm run dev: start the local development server.
- npm run build: create the production bundle in dist/.
- npm run preview: serve the built bundle locally for preview.

SUPABASE CONFIGURATION
----------------------
Supabase is optional for launching the front end. To enable real accounts and cloud features, create a Supabase project and set these environment variables in a local .env file:
- VITE_SUPABASE_URL
- VITE_SUPABASE_PUBLISHABLE_KEY

The older VITE_SUPABASE_ANON_KEY variable is also accepted. The browser app must only use a public/publishable anon key; a service-role secret must never be put in client-side configuration.

Run supabase/schema.sql in the Supabase SQL editor. Configure the local and deployed app URLs in Supabase Auth redirect/site settings. Booking approvals require an admin user's trusted app_metadata role to be set to admin; the user should sign out and back in after the claim is changed. Database row-level security policies also enforce access for workspace data and booking decisions.

Without valid Supabase credentials, the Supabase client is null. Sign-up, sign-in, cloud saving, booking submission, and guest share creation then report that they need Supabase. An optional offline demo mode is present in the app, but workspace state in that mode is temporary and is not durable cloud storage.

APPLICATION ROUTES
------------------
- / : Overview dashboard.
- /studio : Design Studio canvas and editing tools.
- /templates : Explore Templates catalog with search/filter/favorites and launch into the studio.
- /designs : My Designs workspace listing.
- /moodboards : Moodboard records.
- /decorators : Find Decorators screen.
- /bookings : User booking requests.
- /admin and /admin/bookings : Admin booking request review (the latter redirects to /admin).
- /settings : Profile and preferences.

MAIN FEATURES
-------------
1. Design Studio
   - Layered event-decoration scene editor with visual elements for flowers, backdrops, furniture, fabrics, lighting, and props.
   - Add elements to a canvas, select and manipulate them (including drag, resize, and rotate), and edit properties. 
   - Theme presets, arrangement/design settings, zoom and preview controls, and undo/redo support.
   - Venue/floor-plan mode with optional plan image and dimensions/grid settings.
   - Export the canvas as PNG and design data as JSON; save designs to the workspace when cloud persistence is available.

2. Templates and visual library
   - Bundled starter layouts are editable examples, rather than real client/event records.
   - Template discovery includes search, filters, favorites, and opening a template in the editor.
   - Data files define a library of reusable decoration elements and theme palettes.
   - Local template images live under public/images/templates/.

3. Workspace and dashboard
   - Overview surfaces recent designs, event/workspace information, and palette ideas.
   - My Designs and Moodboards are workspace collections with create/save/delete/favorite flows where implemented.
   - Settings maintain profile and language preferences.
   - The app context holds current workspace data and exposes actions to pages/components.

4. Sharing and feedback
   - Signed-in users can create a share snapshot and URL at /share/:shareId.
   - A guest can view the shared design and submit comments or approve/request changes.
   - Share snapshots are stored in the shared_designs table; the share UUID functions as the link credential.

5. Booking requests and administration
   - Signed-in users can submit and manage event booking requests with event date/type, venue, notes, and optional design/vendor details.
   - Admins can review requests and set their status to confirmed or declined.

DATA AND SECURITY MODEL
-----------------------
- public.user_data stores one JSON workspace payload per authenticated user. Its row is keyed by auth.users.id and protected so a user can access only their own row.
- The workspace payload contains items such as designs, moodboards, profile, favorites, locale, notifications, and active design selection.
- public.booking_requests stores individual requests. Owners can read/delete their own requests; users can submit pending requests; only accounts with the trusted admin role can review all requests and change status.
- public.shared_designs stores design snapshots and guest feedback. Anonymous visitors can read by share id and update feedback fields under the schema's policies. Share links therefore should be treated as public-to-anyone-who-has-the-link.
- Supabase Auth manages the browser auth session. Database row-level security is defined in supabase/schema.sql.

CURRENT PRODUCT LIMITS

- Cloud storage, account access, bookings, and share links depend on Supabase configuration and the deployed database schema.
- Offline demo state is temporary and should not be treated as saved data.

PRESENTATION-READY PROJECT STORY
===============================

SHORT PITCH
-----------
Vedika is a digital workspace for turning event decoration ideas into editable visual plans. It brings inspiration, a visual canvas, reusable design elements, and feedback into one workflow so a person planning an event can communicate a look before the event is set up.

THE PROBLEM
-----------
Event decoration ideas are often spread across reference images, messages, notes, and conversations. That makes it difficult to explain how a space should look, compare variations, or collect feedback from family and collaborators. A written description alone may not communicate layout, colors, or the relationship between décor elements.

THE VEDIKA APPROACH
--------------------
Vedika provides a visual planning workspace. Users can start from a template or a blank canvas, arrange decoration pieces, adjust the design, save it, and share a snapshot for comments or approval. The app also keeps related moodboards and booking requests in the same workspace. It focuses on concept planning and communication; it does not claim to replace a professional event planner, a venue survey, or a vendor quotation.

WHO IT IS FOR
-------------
Primary users:
- People planning weddings, birthdays, cultural celebrations, and other events.
- Families and collaborators who need to discuss and approve a visual concept.
- Event decoration professionals who want a lightweight way to sketch and share a concept (the project does not currently provide a verified vendor marketplace).

USER NEEDS ADDRESSED
--------------------
- Explore a starting look without building a design from scratch.
- Make visual changes by placing and arranging elements on a canvas.
- Keep a design and moodboard together in a workspace.
- Share a design with guests or collaborators for feedback.
- Track a booking request and let an administrator review it.
- Use the interface in English or Telugu.

TYPICAL USER JOURNEY
--------------------
1. The user opens Vedika and reviews the overview.
2. They browse templates or open the Design Studio directly.
3. They choose a theme and add flowers, backdrops, furniture, lighting, fabrics, and props.
4. They position and adjust the objects, refine the visual arrangement, and use undo/redo as needed.
5. They save the design, export a PNG/JSON when appropriate, or create a guest share link.
6. A collaborator views the shared snapshot, comments, approves it, or asks for changes.
7. If relevant, the user submits a booking request for administrative review.

PRODUCT VALUE
-------------
- Visual clarity: a canvas makes a concept easier to discuss than text alone.
- Faster iteration: templates and a reusable object library provide a starting point.
- Collaboration: a share view collects comments and a simple approval/request-changes response.
- Organization: designs, moodboards, preferences, and requests are grouped in the workspace.
- Accessibility of context: responsive navigation and English/Telugu options support different devices and users.

WHAT MAKES THE PROJECT DISTINCT (BASED ON THE IMPLEMENTATION)
-------------------------------------------------------------
- It combines an editable decoration canvas with template discovery and guest feedback in one app.
- Its bundled library includes both broadly familiar styling objects and South Asian celebration details such as mandaps, marigolds, rangoli, diyas, torans, and kalash.
- It supports a lightweight booking request workflow alongside visual planning.
- It can run as a front-end demo without a configured backend, while durable accounts and cloud workflows require Supabase.
